1. Repository: openhab/openhab-android
   Outcome: closed
   Proposal: Fix updateHttpClientForClientCert
   Maintainer said: Thanks for the contribution and for the detailed write-up! As far as I can tell, this finding is a false positive for the OkHttp path. OkHttp already rejects TLS 1.1 and older by default, so filtering the protocols on the socket ourselves doesn't change anything. In OkHttp 5.5.0 (the version we use): - OkHttpClient uses DEFAULT_CONNECTION_SPECS = listOf(ConnectionSpec.MODERN_TLS, ConnectionSpec.CLEARTEXT) (OkHttpClient.kt). - MODERN_TLS only allows TlsVersion.TLS_1_3 and TlsVersion.TLS_1_2. TLS 1.0 and 1.1 are only in COMPATIBLE_TLS, which you have to opt into explicitly (ConnectionSpec.kt). - Before every handshake, ConnectionSpec.apply() intersects sslSocket.enabledProtocols with those versions and sets the result on the socket. That's the same filtering this PR adds by hand. We don't override connectionSpecs anywhere, so the default applies. The generic "TLS" argument to SSLContext.getInstance() is fine here: it picks the provider, and the protocol versions are then restricted per socket.

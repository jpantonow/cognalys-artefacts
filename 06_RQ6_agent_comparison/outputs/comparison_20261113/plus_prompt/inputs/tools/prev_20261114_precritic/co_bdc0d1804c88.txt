   Outcome: closed
   Proposal: Migrate widget artwork hashes to SHA-256
   Maintainer said: Thanks for the PR! This hash only names the widget’s cached cover files, so it does no security work, and switching it means migrating files for no gain. I’ll leave it as it is and close this.

2. Repository: javalc6/rssreader
   Outcome: closed
   Proposal: Write file checksums with SHA-256
   Maintainer said: Thanks for taking the time to run the app under RVSec, but it will not be merged. In _FileManager_, MD5 is used only as a checksum to detect accidental corruption of a backup file. It isn’t used for authentication, signatures, or password hashing, so MD5’s known weaknesses (collision attacks) don’t apply here. Since there’s no secret key, switching to SHA-256 wouldn’t stop anyone from modifying a file and recomputing a valid checksum, so it wouldn’t improve security. The _MessageDigestSpec_ warning is a generic rule that flags MD5 regardless of how it’s used. Note that _MessageDigest.getInstance("MD5")_ isn’t rejected by the Java/Android API [MessageDigest](https://developer.android.com/reference/java/security/MessageDigest)
